# Small-workbook opening cost

Issue #51 measures `small.xlsx`, generated by `bench/generate.rb`: 100 data rows,
a header, and 20 columns. This investigation compares commit `e979933` with the
small-workbook snapshot and reader changes on Ruby 3.4.12, Apple M5 Pro,
Darwin 25.6.0. Both extensions use release builds.

## Measurements

Each number is the median of nine fresh Ruby processes. Before and after runs
alternate on the same fixture. `bench/scenario.rb` includes opening the workbook;
it excludes loading the library. Times are milliseconds.

| Scenario | Before | After | Less time |
|---|---:|---:|---:|
| Streaming | 2.637 | 2.077 | 21.2% |
| `parse(headers: true)` | 2.249 | 1.974 | 12.2% |
| `each` | 2.127 | 1.921 | 9.7% |
| 10,000 random `cell` reads | 7.795 | 7.612 | 2.3% |
| `to_csv` | 2.327 | 2.068 | 11.1% |
| Values only | 2.163 | 1.956 | 9.6% |

Peak process RSS stays about 41–42 MiB. This change removes filesystem work;
it does not close the memory gap with calx. The small `cell` difference is too
small to claim a meaningful lookup improvement.

`bench/open.rb` instruments opening and the first streaming read. Its step times
exclude time in nested measured steps. Instrumentation adds overhead, and
independent medians do not sum exactly to the median total.

| Opening step | Before | After | Decision |
|---|---:|---:|---|
| Temporary directory | 0.152 | 0.143 | Keep for roo's extractors, fallback files, `tmpdir_root`, and close/GC behavior. |
| Snapshot | 0.222 | 0.043 | Keep ZIPs up to 256 KiB in memory instead of copying to disk. |
| rubyzip central directory | 0.336 | 0.084 | Read from the memory stream; retain rubyzip's entry and error semantics. |
| Native entry objects | 0.057 | 0.043 | Keep offsets, sizes, compression, and fallback information for deferred reads. |
| Metadata inflation | 0.073 | 0.037 | Read from shared snapshot bytes without reopening the ZIP for each part. |
| Workbook XML | 0.048 | 0.047 | Keep roo's sheet names, order, date system, and labels. |
| Sheet IDs | 0.053 | 0.049 | Keep roo's sheet ordering and relationship matching. |
| Workbook relationships | 0.027 | 0.027 | Keep roo's worksheet-type and target handling. |
| Other extraction | 0.137 | 0.196 | Includes shared-buffer setup and roo's remaining sheet-relationship file. Keep its path for roo's extractors. |
| `Sheet` objects | 0.008 | 0.007 | Keep roo's per-sheet options and API. |
| Other initialization | 0.086 | 0.054 | File/options validation and roo's base initialization. |
| Total `Roo::Excelx.new` | 1.183 | 0.741 | 37.4% less time in this instrumented measurement. |

Styles XML is already lazy in roo: opening does not parse it. The first
streaming read spends 0.029 ms in styles both before and after. Deferring it
again would add another layer without removing the work a styled cell needs.

Starting the streaming reader falls from 0.024 to 0.005 ms. Entries below
256 KiB inflated use the existing batch parser on demand, with the GVL released.
Larger entries retain their parsing and inflation workers. The compressed ZIP
threshold bounds retained snapshot memory independently of inflated entry size.

## Why random `cell` reads cost more

After opening and parsing, the benchmark precomputes the same 10,000 coordinates
and reads them twice. Before the change, the first pass takes 5.050 ms and a
cached pass takes 3.161 ms. The first pass builds up to 2,020 roo cell objects.
Querying the sheet directly takes 1.618 ms; querying the native store directly
takes 1.110 ms. The difference is roo's sheet resolution and validation, the
Ruby wrappers, and checking the cell's public value method. The end-to-end
scenario also includes opening, parsing, and random-coordinate generation.

Keep those semantics: sheet errors, normalization, mutable values, and cell
identity must still agree with roo. `Store#build` now checks its existing cell
before looking for a value handed out earlier, avoiding that unused lookup on
cache hits. A larger redesign of `cell` is outside this opening-cost change.

## Reproduce

Generate the standard fixtures with `cd bench && bundle exec ruby generate.rb`.
From the repository root, build with `bundle exec rake compile`, then run:

```sh
bundle exec ruby -Ilib bench/open.rb bench/fixtures/small.xlsx
BUNDLE_GEMFILE=bench/Gemfile bundle exec ruby -Ilib bench/scenario.rb roo-calamine stream bench/fixtures/small.xlsx
BUNDLE_GEMFILE=bench/Gemfile bundle exec ruby -Ilib bench/scenario.rb roo-calamine stream bench/fixtures/small.xlsx digest
```

Repeat each command in fresh processes and take the median. Use the same
fixture for both revisions. Run all six scenarios by replacing `stream` with
`parse`, `each`, `cell`, `csv`, or `values`. All six digest results match plain
roo in this investigation.

The snapshot follows [rubyzip's existing stream reader](https://github.com/rubyzip/rubyzip/blob/v3.3.0/lib/zip/central_directory.rb)
and [Rust's `Cursor` API](https://doc.rust-lang.org/std/io/struct.Cursor.html).
The native entries share one owned byte buffer; no new ZIP parser or dependency
is introduced. Empty files, unsupported entries, packed inputs, and large
workbooks retain their existing extraction paths.
